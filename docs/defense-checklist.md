# 答辩演示清单

## 1. 演示前检查

建议至少提前一天在答辩使用的电脑和网络环境执行：

```bash
cd frontend
npm ci
npm run lint
npm run build

cd ../backend
./mvnw test

cd ..
docker compose config --quiet
docker compose up -d --build
```

启动后确认：

- `http://localhost` 可以登录，默认本地账号为 `admin / 123456`
- 首页设备、任务、宠物和告警数据能够加载
- 萤石设备在线，直播地址仍在有效期内
- DeepSeek 与 MiMo Key 可用，账户余额充足
- 手动检测、AI 分析、告警已读各成功执行一次
- 浏览器缩放为 100%，关闭无关通知和开发工具

## 2. 推荐演示主线

控制在 6 至 8 分钟，围绕一个完整业务闭环展开：

1. 登录并介绍首页运行状态，不逐页念菜单。
2. 展示萤石 OAuth 绑定和当前用户设备隔离。
3. 创建或打开宠物档案，说明数据归属用户。
4. 展示检测任务和百分比坐标安全区域。
5. 手动执行一次检测，查看坐标、截图和安全区判断。
6. 打开异常告警，说明冷却、已读和实时 SSE 推送。
7. 用一条已有记录生成 AI 报告，强调 AI 只提供辅助建议。
8. 最后展示 Swagger、数据库关系和 CI，证明工程完整性。

## 3. 外部服务故障预案

萤石、DeepSeek 和 MiMo 都依赖公网，现场不要把成功完全押在实时调用上。

- 提前保留一条检测记录、一条告警和一份 AI 报告。
- 准备 30 至 60 秒录屏，覆盖设备绑定、直播和 AI 分析成功过程。
- 实时调用失败时先说明外部依赖边界，再展示已有结果和原始证据字段。
- 不在答辩现场修改 Key、数据库或 Docker 配置。

## 4. 常见追问

### 为什么选择 Spring Boot 和 React？

后端需要承载认证、定时任务、第三方平台调用和数据隔离，Spring Boot 的分层与生态适合快速构建；React 负责状态化管理页面，并通过 TypeScript降低接口联调错误。

### 如何判断宠物越界？

模型返回宠物检测框后取中心点，矩形区域使用边界比较，多边形区域使用射线法；区域采用百分比坐标，因此不依赖固定视频分辨率。

### 如何避免重复告警？

检测任务配置冷却时间，异常消失、异常活跃和长时间静止分别判断；告警表还使用平台告警 ID 和设备序列号做幂等约束。

### 如何保证用户只能访问自己的设备？

JWT 提供当前用户身份，用户与设备通过 `user_device` 绑定；设备、视频、告警和检测查询在服务层按绑定范围过滤，写操作还会校验角色。

### AI 结果可靠吗？

AI 结果是辅助判断，不替代兽医诊断。报告保存图片、检测数据、模型、提示词版本和不确定性，便于追溯；外部模型失败时业务主流程仍可查看检测与告警记录。

### 目前最大的局限是什么？

当前定位是单实例 Demo：外部 API 稳定性、检测阈值泛化、前端自动化测试、接口限流和高可用部署仍需继续完善。
